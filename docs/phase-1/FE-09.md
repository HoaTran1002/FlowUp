# FE-09 — Usage Dashboard, Accessibility and Responsive Pass

**Task (`IMPLEMENTATION_PLAN.md` §4):** usage dashboard, responsive/accessibility pass, empty/error/loading states, test IDs.
**Dependencies:** `BE-11`, `FE-01`, `FE-06`, `FE-07`.
**Requirements:** `UI-02`, `UI-10`, `FR-OBS-06`. Tests: `UX-AC-10`, `QA-UI-01`, `QA-UI-03`, `QA-UI-04`, `QA-UI-05`, `QA-UI-08`.

**Normative inputs:** `UI_UX_SPECIFICATION.md` §3 UI-02/UI-10, §4.1 wireframe, §5; `API_SPECIFICATION.md` §5 (`/usage/summary`); `PRD.md` §3 F08.

## Scope boundary

In scope: `/app/overview` with the KPI cards, date filter and recent-failures table; plus a cross-cutting pass over every screen built so far for accessibility, responsiveness, state completeness and stable test IDs.

Out of scope: new business screens; new aggregations beyond the documented counts. Extended dashboard analytics are P1 or post-MVP (`PRD.md` §9).

## Implementation requirements

1. **KPI cards (`UI-02`).** Accepted events, succeeded deliveries, final failed deliveries and pending deliveries, from `GET /v1/usage/summary` only. Use the server's counts verbatim — no client-side derivation, no projection, and no hardcoded sample numbers in a production dashboard (`apps/web/AGENTS.md` §6).
2. **Date filter.** Apply the date-range semantics documented by `BE-11` consistently with the events and deliveries screens (`UI_UX_SPECIFICATION.md` §7.4). Keep the selection in search parameters so the view is shareable and restorable.
3. **Recent failures.** A bounded list of recent failed deliveries with status, event, endpoint, last error and time, plus a "view all failures" link into `/app/deliveries` with the status filter pre-applied (`UI_UX_SPECIFICATION.md` §4.1). Reuse the `FE-07` status vocabulary — do not re-label anything here.
4. **No billing implication.** The usage summary carries no commercial meaning; present it as operational counts only (`API_SPECIFICATION.md` §5).
5. **State completeness pass.** Verify every screen from `FE-02`..`FE-08` renders loading, empty, filtered-empty, success, error, `403` and `404` states, and that no screen claims success on an error (`QA-UI-01`, `QA-UI-05`). Fix gaps in this task rather than deferring them.
6. **Accessibility pass** (`UI_UX_SPECIFICATION.md` §5, `apps/web/AGENTS.md` §7): keyboard navigation across every route, dialog and table; visible focus indicators; labels and aria descriptions; accessible names on icon-only controls; WCAG AA contrast; status conveyed by text and icon rather than colour alone; loading states announced to assistive technology (`QA-UI-03`, `QA-UI-04`).
7. **Responsive pass.** Every screen usable at mobile, tablet and desktop widths: collapsed navigation, horizontally scrolling tables, truncation with tooltips for long IDs and URLs, and no layout shift when filtering or sorting (`QA-UI-04`).
8. **Filter and cursor consistency.** Confirm across events and deliveries that filter changes reset the cursor, filters survive back navigation, and pagination controls are accessible (`QA-UI-08`, `UX-AC-09`).
9. **Global error UX (`UI-10`).** Error page, access denied, expired session, copy-success feedback, and a `429` banner with retry guidance — all using the shared error envelope's safe message and `request_id` (`UX-AC-10`, `QA-UI-05`).
10. **Test IDs.** Add stable `data-testid` hooks on navigation, tables, rows, dialogs, status indicators and primary actions, so `FE-10` can target them without brittle text matching. Keep them stable thereafter.
11. **Timezone clarity.** Timestamps use the single `FE-01` formatting helper with an explicit timezone indication on every screen, while the API's UTC values remain authoritative (`apps/web/AGENTS.md` §6).

## Tests

- **Unit:** usage response mapping; date-range parameter normalization.
- **Component:** KPI cards with populated, zero, loading and error data; recent-failures empty state; `429` banner.
- **Accessibility:** automated axe-style checks per route plus manual keyboard traversal; contrast verification.
- **Responsive:** mobile, tablet and desktop smoke per route, asserting no horizontal page scroll.

## Definition of Done

The overview renders honest server-derived counts with a consistent, restorable date filter and a link into filtered failures; every screen's state matrix is complete; accessibility and responsive requirements are met and verified, not assumed; global error UX including `429` and session expiry works; stable test IDs are in place; listed tests pass. No new aggregation or metric was invented.
