# BE-13 — Rate Limits, Retention, Metrics, Health and Operations Runbook

**Task (`IMPLEMENTATION_PLAN.md` §3):** rate limits, retention/redaction jobs, metrics/health, deployment config and secure operations runbook.
**Dependencies:** `BE-05`, `BE-09`..`BE-12`.
**Blocked by:** **ADR-04** — payload cap, per-organization throughput, endpoint count, retention windows, timeout and retry horizon. `TEST_PLAN.md` §7 states retention may be tested only after these limits are approved. Implement the mechanisms now and the numbers as configuration.
**Requirements:** `FR-SEC-03`, `FR-SEC-05`, `FR-SEC-06`, `NFR-07`..`NFR-10`. Tests: `QA-SEC-09`, performance and operations smoke (`TEST_PLAN.md` §7).

**Normative inputs:** `SYSTEM_ARCHITECTURE.md` §7 (telemetry, alerts) and §8 (capacity); `TECHNICAL_DESIGN.md` §10 (deployment checklist); `DATABASE_DESIGN.md` §6 (retention) and §7; `PRD.md` §7.

## Scope boundary

In scope: rate limiting and payload caps, the retention and redaction jobs, metrics and health/readiness completion for all processes, deployment configuration, alert definitions, and the operations runbook.

Out of scope: new business behavior of any kind. This task hardens what exists; it must not change a delivery, retry or replay semantic.

## Implementation requirements

1. **Rate limits** (`FR-SEC-03`). Bound publish throughput per organization and per credential, and bound failed-authentication attempts. Return `429` with `Retry-After` when known, using the shared error envelope. A rate-limited publish creates no event (`QA-SEC-09`). Limits are configuration (`RATE_LIMIT_*`), with the pilot proposals as defaults; they are not contractual SLAs (`PRD.md` §7).
2. **Payload cap.** Enforce the configured request body limit, returning `413` and creating no event. Coordinate with the `BE-01` body-size configuration so one limit governs (`PRD.md` §7 proposal: 256 KiB).
3. **Retention jobs** (`FR-SEC-05`, `DATABASE_DESIGN.md` §6). Scheduled deletion or redaction of event payloads and attempt detail past `retention_until`, with separate policies for audit metadata and idempotency tombstones. Hard constraints:
   - Never remove an event payload while retry or replay eligibility remains.
   - Never delete audit history to simplify anything.
   - Never allow an idempotency key to become reusable before the advertised retry horizon expires.
   - Deletion must not corrupt metadata or audit boundaries (`NFR-09`).
   Jobs must be idempotent, bounded per run, cancellable, and observable.
4. **Health and readiness.** Complete the probes for `api`, `dispatcher` and `worker` begun in `BE-01`: liveness distinct from readiness, with readiness reflecting PostgreSQL, Redis and migration state (`TECHNICAL_DESIGN.md` §10).
5. **Metrics** (`SYSTEM_ARCHITECTURE.md` §7). Accepted events; deliveries active, succeeded and failed; queue backlog and oldest age; dispatcher lag; delivery p50/p95 latency; retry counts; endpoint error categories; worker lease expiries; DB connection saturation. Measure before promising: start with instrumentation, not SLOs (`NFR-10`).
6. **Alerts.** Define, with thresholds as configuration: outbox oldest pending age; retry-wait age; dispatcher failures; worker lease expirations; share of `5xx` deliveries; DB connection saturation; Redis memory and eviction state (`SYSTEM_ARCHITECTURE.md` §7, `TEST_PLAN.md` §7).
7. **Structured logging completeness.** Verify every log record carries the field contract from `BE-01` and that redaction holds across the paths added since: attempts, errors, traces and diagnostics. PII in payloads must be redacted from logs (`FR-OBS-05`, `apps/api/AGENTS.md` §6).
8. **Deployment configuration** (`TECHNICAL_DESIGN.md` §10). Fail-fast env schema coverage for every new variable; secrets from a deployment secret manager, never the repository; production HTTPS; DB connection pool sizing across the three processes; bounded worker concurrency; Redis `noeviction` plus persistence and memory alarms; graceful shutdown that stops claiming, drains within a deadline and leaves leases recoverable.
9. **Runbook** (deliverable document). Must cover: PostgreSQL backup and a rehearsed restore drill; migration and rollback procedure; Redis loss recovery via the reconciler; dispatcher and worker restart; responding to an aged outbox alert; rotating `SECRET_ENCRYPTION_KEY` and endpoint secrets; revoking a leaked API key; investigating a delivery without direct database access; and the explicit statement that at-least-once delivery permits consumer duplicates.
10. **Performance smoke** (`TEST_PLAN.md` §7). Run the proposed pilot load — 10 organizations, 1,000 endpoints, 100 events/minute burst, fan-out to 10, 1–16 KiB payloads — and record p50/p95 publish latency, queue lag, due-delivery lag, attempt completion latency, DB and Redis growth, and worker throughput. Report measurements as trial conditions, never as guaranteed SLAs (`NFR-10`).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | Exceeding the publish rate limit returns `429` and creates no event | `QA-SEC-09` |
| 2 | An over-cap body returns `413` and creates no event | `QA-SEC-09` |
| 3 | Retention jobs delete only eligible data and never remove a payload still replay-eligible | `NFR-09`, `FR-SEC-05` |
| 4 | Audit history survives every retention run | `FR-SEC-06` |
| 5 | An idempotency key cannot be reused before the advertised horizon | `DATABASE_DESIGN.md` §6 |
| 6 | All three processes expose distinct liveness and readiness, failing correctly when a dependency is down | `TECHNICAL_DESIGN.md` §10 |
| 7 | Every metric in §5 is emitted and queryable | `NFR-08` |
| 8 | Each alert in §6 fires in an injected-fault test | `TEST_PLAN.md` §7 |
| 9 | Graceful shutdown drains work and leaves no unrecoverable lease | `TECHNICAL_DESIGN.md` §10 |
| 10 | A restore drill recovers the database and the system resumes dispatch | runbook |
| 11 | Logs contain no secret, payload or downstream response body | `QA-SEC-07`, `FR-OBS-05` |

## Tests

- **Unit:** limiter decisions and `Retry-After` computation; retention eligibility predicates including the replay-eligibility guard.
- **Integration:** retention run against seeded aged data asserting what is and is not removed; readiness transitions when PostgreSQL or Redis stops; shutdown draining.
- **Operations:** fault-injected alert firing; backup and restore drill; performance smoke with recorded measurements.
- **Security:** `QA-SEC-09`; a log-scan test across all three processes.

## Definition of Done

Rate limits and payload caps enforced as configuration with correct `429`/`413` and no side effects; retention and redaction jobs correct, bounded and safe for replay eligibility and audit history; health, readiness, metrics and alerts complete for all processes; deployment configuration and graceful shutdown per the checklist; runbook written and the restore drill actually performed; performance smoke measured and reported as provisional; no secret or payload in any log. ADR-04 values implemented as configuration with the decision recorded.
