# BE-08 — Outbox Dispatcher, BullMQ Enqueue and Reconciliation

**Task (`IMPLEMENTATION_PLAN.md` §3):** DB outbox dispatcher + BullMQ enqueue, retry enqueue on outage, queue reconciliation.
**Dependencies:** `BE-03`, `BE-07`.
**Requirements:** `FR-RET-04`, `FR-RET-06`, `NFR-01`. Tests: `QA-RES-01`, `QA-RES-03`, `QA-RES-05`, `AT-10`.

**Normative inputs:** `TECHNICAL_DESIGN.md` §4 (dispatcher) — normative for this task; `SYSTEM_ARCHITECTURE.md` §4.3 steps 1 and 7, §5; `DATABASE_DESIGN.md` §3 canonical `outbox_message` columns, §6 partial indexes; `apps/api/AGENTS.md` §5.

## Scope boundary

In scope: the `apps/dispatcher` process — claiming due outbox rows, enqueueing minimal BullMQ jobs, acknowledging enqueue, and the reconciler that recovers work after a Redis outage or a crash.

Out of scope: performing a delivery (`BE-09`), computing the retry schedule (`BE-07` writes the first intent; `BE-10` writes subsequent ones). The dispatcher decides *when to hand work to the queue*, never *whether a delivery should be retried*.

## Implementation requirements

1. **Claim loop.** Poll `outbox_message` where `state = 'PENDING'` and `available_at <= now()`. Claim a bounded batch with `FOR UPDATE SKIP LOCKED` plus a lease (`claim_token`, `lease_until`), setting `state = 'CLAIMED'`. The claim transaction must be short and must contain **no Redis call** (`TECHNICAL_DESIGN.md` §4).
2. **Enqueue outside the transaction.** After commit, call `queue.add('deliver', { deliveryId, generation, attemptNumber }, { jobId: deterministicJobId })`. The payload carries identifiers only — never the event payload, the URL or any secret (`apps/api/AGENTS.md` §6).
3. **Deterministic job ID.** Derive it from `deliveryId:generation:attemptNumber` with characters normalized for BullMQ (`DATABASE_DESIGN.md` §3). It is a de-duplication *optimization*; business correctness comes from the worker's conditional DB claim and generation check, never from job retention (`FR-RET-06`).
4. **Scheduling authority.** The database owns the schedule. **Recommended and adopted:** the dispatcher enqueues only rows that are already due, with no additional BullMQ `delay`, and each job is configured `attempts: 1` (`TECHNICAL_DESIGN.md` §4, `apps/api/AGENTS.md` §5). Do not create a second, queue-level retry loop.
5. **Acknowledge.** Mark the row `ENQUEUED` with `enqueued_at` after Redis accepts the job. A crash between `queue.add` and this update may duplicate the enqueue; that is acceptable and is absorbed by the deterministic job ID and the worker claim (`QA-RES-03`).
6. **Redis outage behavior.** On enqueue failure: do not lose the row. Increment `enqueue_attempts`, release the claim so the row returns to `PENDING` with a bounded backoff in `available_at`, and keep retrying. An accepted event must never become unrecoverable because Redis was unavailable (`NFR-01`, `QA-RES-01`).
7. **Reconciler.** Periodically query PostgreSQL — the source of truth — for: outbox rows whose claim lease expired; `PENDING`/`RETRY_WAIT` deliveries that are due but have no usable queue work; and rows stuck in `ENQUEUED` whose job has vanished. Safely recreate the enqueue intent. A DB row must never become irrecoverable because a BullMQ job was removed (`TECHNICAL_DESIGN.md` §4, `QA-RES-05`).
8. **Idempotent recreation.** The reconciler must respect unique `(delivery_id, generation, attempt_number, kind)` and must not create a conflicting second intent for the same attempt (`QA-DB-02`).
9. **Bounded operation.** Configurable poll interval (`DISPATCHER_POLL_INTERVAL_MS`), batch size and claim lease duration. Back off when idle. Bound the claim lease so a dispatcher crash frees work promptly.
10. **Graceful shutdown.** On `SIGTERM`: stop claiming, finish acknowledging already-enqueued jobs where possible, release unused claims, exit zero. Leave every unfinished row recoverable (`TECHNICAL_DESIGN.md` §10).
11. **Observability.** Emit dispatcher lag, oldest pending outbox age, claim and enqueue failure counts (`SYSTEM_ARCHITECTURE.md` §7). Aged pending outbox is an alert candidate — expose the metric `BE-13` will alert on.
12. **Queue cleanup.** `removeOnComplete`/`removeOnFail` are optional operational tuning only. Authoritative history lives in the database (`TECHNICAL_DESIGN.md` §4).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | Due outbox rows are enqueued exactly once under normal operation | `QA-E2E-02` |
| 2 | Concurrent dispatcher instances never claim the same row simultaneously | `QA-RES-06` prerequisite |
| 3 | Redis unavailable: rows stay recoverable and are dispatched after recovery | `QA-RES-01`, `AT-10` |
| 4 | Crash between enqueue and acknowledgement yields at most one active delivery obligation | `QA-RES-03` |
| 5 | Jobs lost from Redis are recreated from the database by the reconciler | `QA-RES-05` |
| 6 | Job payloads contain only `deliveryId`, `generation`, `attemptNumber` | `apps/api/AGENTS.md` §6 |
| 7 | No BullMQ-level retry is configured; `attempts: 1` per job | `TECHNICAL_DESIGN.md` §4 |
| 8 | No Redis call occurs inside a database transaction | `AGENTS.md` INV-05 |
| 9 | `SIGTERM` leaves no permanently claimed row | `TECHNICAL_DESIGN.md` §10 |

## Tests

- **Unit:** deterministic job ID derivation; claim-release backoff; due-row predicate.
- **Integration:** claim concurrency with `SKIP LOCKED` across parallel dispatchers; enqueue acknowledgement; enqueue failure releasing the claim; reconciler recreating a deleted job and an expired lease; unique-constraint safety on recreation.
- **Resilience:** `QA-RES-01`, `QA-RES-03`, `QA-RES-05` with real Redis stopped and restarted; a code-level assertion (review or test) that no transaction scope contains a Redis call.

## Definition of Done

The dispatcher claims, enqueues and acknowledges correctly with short transactions and no external I/O inside them; jobs carry identifiers only with `attempts: 1`; a Redis outage, a dispatcher crash and a loss of queue jobs all recover from the database with no lost accepted event and no duplicate business obligation; the reconciler respects the outbox unique key; metrics exposed; graceful shutdown leaves everything recoverable; listed tests pass.
