# FE-04 — Endpoints Screens, Subscriptions and Secret Rotation Dialog

**Task (`IMPLEMENTATION_PLAN.md` §4):** endpoints list/form/detail, subscription editing, disable, signing secret rotation one-time dialog.
**Dependencies:** `BE-06`, `FE-03`.
**Blocked by:** **ADR-02** — the rotation dialog must describe the approved cutover policy for pending deliveries. Do not describe a grace window that does not exist, or an immediate cutover if overlap was approved.
**Requirements:** `UI-04`, `UI-05`, `FR-END-01`..`06`. Tests: `UX-AC-01`, `UX-AC-02`, `UX-AC-08`, `QA-UI-02`, `QA-UI-07`, `QA-SEC-07`, `QA-E2E-09`.

**Normative inputs:** `UI_UX_SPECIFICATION.md` §3 UI-04/UI-05, the UI-05 validation and secret-lifecycle subsections, §4.2 wireframe, §5; `API_SPECIFICATION.md` §4 (endpoints, rotate-secret).

This task handles a credential shown exactly once. Secret hygiene is the dominant risk.

## Scope boundary

In scope: `/app/endpoints` list, `/app/endpoints/new`, `/app/endpoints/:endpointId` detail and edit, subscription editing, enable and disable, and the one-time secret dialog for creation and rotation.

Out of scope: API keys (`FE-05`), deliveries (`FE-07`). The frontend never verifies a signature and never stores a secret.

## Implementation requirements

1. **List (`UI-04`).** Application, hostname, status and subscribed event types, with filters and a create CTA. Show the hostname rather than the full URL where space is constrained, truncating long URLs with a tooltip and no layout shift (`apps/web/AGENTS.md` §7).
2. **Form (`UI-05`).** Required: application picker, name, public HTTPS URL, and a **non-empty** subscription list. Event types render as removable chips. Give immediate client-side feedback for a syntactically invalid URL while stating that the server is authoritative for DNS, IP and SSRF decisions (`UI_UX_SPECIFICATION.md` §3 UI-05).
3. **Server-side URL errors.** Surface the server's `422` SSRF and validation errors accurately — private address, credentials in URL, prohibited port, unsupported protocol — without inventing a reason or implying the client could have allowed it (`FR-SEC-02`, `QA-SEC-04`).
4. **URL change notice.** When editing a URL, show the inline notice that the change affects **future deliveries only**; existing deliveries keep their snapshotted target (`FR-END-01`, `PRD.md` §6 edge case 6, `QA-E2E-10`).
5. **Disable (`UX-AC-08`).** Confirmation dialog with the specified copy: unsent pending deliveries will be cancelled, and in-flight requests may finish. Refresh statuses after the mutation; claim no abort of an in-flight request (`FR-END-06`).
6. **One-time secret dialog** (`UI_UX_SPECIFICATION.md` §3 UI-05 secret lifecycle, `QA-UI-02`):
   - Opens on creation and on rotation, showing the secret with `Reveal` and `Copy`.
   - Requires an explicit **"I have stored this secret securely"** acknowledgement before closing.
   - Keeps the raw value in ephemeral component state only; clears it on close, navigation and unmount; never refetches it (`apps/web/AGENTS.md` §4).
   - The secret must never enter the query cache, a persister, `localStorage`, a URL, a toast, analytics, telemetry, an error report or a test snapshot (`QA-SEC-07`, `UX-AC-02`).
   - After a refresh, the secret is gone and the detail page shows version metadata only, with a rotate action and verification instructions.
7. **Rotation.** Confirmation before rotating, explaining the approved ADR-02 effect on pending deliveries. Treat rotation as destructive: it requires confirmation and produces a new one-time dialog (`QA-UI-07`).
8. **States.** Loading, empty, success, error and validation error across list, form and detail; `403` and `404` as established in `FE-02`.
9. **Accessibility.** Dialog focus management, keyboard-operable chips, labeled fields, first invalid field focused, status by text not colour.
10. **Query hygiene.** Invalidate the endpoint list and affected detail after a mutation. Nothing that could carry a secret may be cached (`apps/web/AGENTS.md` §6).

## Tests

- **Unit:** URL and subscription form schema; chip add and remove; dialog state machine including acknowledgement gating and clearing on unmount.
- **Component:** one-time dialog lifecycle with an assertion that the value is unreachable after close; disable and rotate dialogs; server-error rendering.
- **Integration (mocked API):** create → dialog → refresh shows no secret; rotate → new dialog; `422` SSRF path; disable → status refresh.
- **Security:** tests asserting the secret never appears in the query cache, browser storage, a URL, or any snapshot; no fixture contains a realistic secret.

## Definition of Done

List, form, detail, subscription editing, disable and rotation implemented against the contract; the one-time secret dialog requires acknowledgement, keeps the value ephemeral and leaves no trace anywhere; server SSRF and validation errors shown accurately; the future-only URL notice and the disable warning match the approved semantics; ADR-02 rotation behavior described correctly or reported as blocking; accessibility met; listed tests pass including the secret-absence assertions.
