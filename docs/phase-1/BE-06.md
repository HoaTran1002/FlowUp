# BE-06 — Endpoints, Subscriptions, URL Validation and Signing Secrets

**Task (`IMPLEMENTATION_PLAN.md` §3):** endpoints CRUD, subscriptions, URL validation, encrypted/versioned secret, disable/rotation policy.
**Dependencies:** `BE-02`, `BE-03`, `BE-04`.
**Blocked by:** **ADR-02** — immediate vs overlap signing-secret rotation, and which version a pending delivery uses. The table structure is settled; the cutover semantics are not.
**Requirements:** `FR-END-01`..`06`, `FR-SEC-02`, `FR-SEC-04`, `FR-SEC-06`. Tests: `QA-E2E-09`, `QA-E2E-10`, `QA-SEC-01`..`04`, `QA-SEC-06`, `QA-SEC-07`.

**Normative inputs:** `PRD.md` §3 F04 and §6 edge cases 5–7; `API_SPECIFICATION.md` §4; `DATABASE_DESIGN.md` §3 (endpoint, subscription, secret version), §4; `TECHNICAL_DESIGN.md` §6 (SSRF-safe egress) and §7 (secrets); `UI_UX_SPECIFICATION.md` §3 UI-05.

## Scope boundary

In scope: endpoint CRUD, subscription management, the URL safety validator used at configuration time, signing-secret provisioning, versioning and rotation, and the disable policy.

Out of scope: the send path (`BE-09` owns connection-time revalidation, IP pinning and signing); the UI dialog (`FE-04`). This task owns the *validator*, which `BE-09` reuses — it must not be reimplemented there.

## Implementation requirements

1. **Routes exactly as specified** (`API_SPECIFICATION.md` §4):
   - `POST /v1/endpoints` with `{ application_id, name, url, event_types[] }` → `201` with endpoint metadata, `status: "ENABLED"`, and `signing_secret` **shown exactly once**.
   - `GET /v1/endpoints` → cursor-paginated metadata, never a secret.
   - `PATCH /v1/endpoints/{id}` accepting `name`, `url`, `status`, `event_types`.
   - `POST /v1/endpoints/{id}/rotate-secret` → new secret once, plus key version and activation details.
2. **Scoping.** The endpoint belongs to an application owned by the principal's organization; a non-owned application or endpoint ID returns `404`. Both Admin and Developer may manage endpoints.
3. **Subscriptions.** A non-empty list is required (`UI_UX_SPECIFICATION.md` §3 UI-05 product rule). Normalize and bound event-type strings against the suggested pattern `^[a-z][a-z0-9_.-]{0,99}$` (`API_SPECIFICATION.md` §3). Enforce unique `(endpoint_id, event_type)`. A `PATCH` replacing the list is a set operation, not an append.
4. **URL validation at configuration time** (`FR-END-02`, `FR-SEC-02`, `TECHNICAL_DESIGN.md` §6). Reject with `422`: non-HTTPS schemes; embedded credentials; fragments; non-allowlisted ports; normalization tricks; hostnames resolving only to non-globally-routable addresses. Resolve A and AAAA records and require **all** candidate IPs to be public, covering IPv4, IPv6, IPv4-mapped IPv6, loopback, private, link-local, multicast, reserved and cloud-metadata ranges. Configuration-time validation does **not** replace send-time validation — document that both run (`SYSTEM_ARCHITECTURE.md` §4.1).
5. **Secret provisioning.** Generate with a CSPRNG. Encrypt with authenticated encryption using the deployment-managed key from `SECRET_ENCRYPTION_KEY`; store `version` and, where the policy requires, `expires_at` (`TECHNICAL_DESIGN.md` §7). The plaintext is returned only in the creation or rotation response and is never retrievable again — no read route, no admin escape hatch, no log line (`FR-END-03`, `QA-SEC-07`).
6. **Rotation under ADR-02.** Use `endpoint_secret_version` rather than overwriting a secret that a pending delivery still references (`DATABASE_DESIGN.md` §3). Implement whichever policy is approved — immediate cutover, or overlap with a grace window — and make it explicit in the API documentation and in the response. A phase-1 immediate rotation is acceptable **only** if pending sends are intentionally migrated or cancelled with documented behavior. If ADR-02 is unresolved, implement the versioned storage and report the cutover semantics as blocking.
7. **Delivery snapshot contract.** Deliveries snapshot `target_url_snapshot` and `secret_version_id` at acceptance (`BE-07`). Therefore a later URL change affects **future** deliveries only, and must not rewrite existing ones (`FR-END-01/06`, `PRD.md` §6 edge case 6, `QA-E2E-10`). Expose the secret version an acceptance should snapshot; do not let `BE-07` guess it.
8. **Disable semantics** (`FR-END-06`): no new attempts are scheduled; unsent pending deliveries are cancelled; an HTTP call already in flight may finish. Implement cancellation as a state transition to `CANCELLED` consistent with `DATABASE_DESIGN.md` §4, and make the worker's enabled-check authoritative at claim time (`BE-09`). Never claim an in-flight request was aborted.
9. **Audit.** Create, update, disable, enable and rotate produce `audit_log` entries with actor, organization, endpoint and a safe delta — URL host may be recorded, secret material never (`FR-SEC-06`).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | Endpoint created under an owned application with a non-empty subscription list | `QA-E2E-01` |
| 2 | Signing secret returned once at creation and at rotation only | `QA-SEC-07`, `UX-AC-02` |
| 3 | `localhost`, RFC1918, loopback, link-local, reserved and cloud-metadata URLs are rejected at configuration | `QA-SEC-01` |
| 4 | URL with credentials, unsupported protocol or prohibited port returns `422` and no endpoint is enabled | `QA-SEC-04` |
| 5 | A hostname whose DNS answer includes a non-public IP is rejected | `QA-SEC-02` (configuration half) |
| 6 | Updating a URL leaves existing pending deliveries on the snapshotted target | `QA-E2E-10` |
| 7 | Disabling cancels unsent pending deliveries and schedules no new attempt | `QA-E2E-09`, `AT-11` |
| 8 | Rotation leaves pending deliveries resolvable under the documented ADR-02 policy | `QA-SEC-06` |
| 9 | Cross-tenant endpoint ID returns `404`; no secret, URL or existence leak | `QA-AUTH-02` |
| 10 | Ciphertext at rest is authenticated; no plaintext secret column exists | `FR-SEC-04` |

## Tests

- **Unit:** the URL policy validator against an explicit allow/deny table covering every range and trick in `TECHNICAL_DESIGN.md` §6; event-type normalization; subscription set replacement; secret version selection.
- **Integration:** CRUD and rotation against PostgreSQL; unique subscription constraint; disable cancelling pending deliveries; version rows retained for pending references.
- **Security:** `QA-SEC-01`..`04`, `QA-SEC-06`, `QA-SEC-07`. Use a controlled test resolver — never probe real internal infrastructure (`TECHNICAL_DESIGN.md` §6, `TEST_PLAN.md` §9).

## Definition of Done

Four routes matching the contract; subscriptions validated and unique; the URL validator rejects every documented unsafe class and is the single shared implementation reused by `BE-09`; secrets encrypted, versioned and revealed once; the ADR-02 rotation policy implemented and documented or reported as blocking; disable semantics exact and honestly described; audit entries written; listed tests pass.
