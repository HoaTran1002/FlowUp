**Prerequisites:** read `AGENT_ADAPTER.md`, root `AGENTS.md`, `apps/web/AGENTS.md`, and `README.md` §4–§8 of this folder. Do not start without them.

`FE-01` may begin against mocks before the backend business endpoints exist, but `packages/contracts` and the error/pagination envelopes from `BE-01` must be available first.

## 4. Step 3 — Routing (D3)

Build the exact route tree from `UI_UX_SPECIFICATION.md` §2 — no invented routes:

```text
/login                      (placeholder only; bootstrap blocked by ADR-01)
/app
  /overview
  /applications
  /applications/:applicationId
  /endpoints
  /endpoints/new
  /endpoints/:endpointId
  /events
  /events/:eventId
  /deliveries
  /deliveries/:deliveryId
  /api-keys                 [Admin only]
  /settings                 [read-only in pilot]
```

Rules:

- `/app/*` sits under one authenticated layout route that renders the shell.
- Every leaf is a placeholder page in phase 1, stating which `FE-XX` task will implement it. A placeholder must not fake data or a success path.
- `/` redirects to `/app/overview`; unknown paths render the 404 route.
- List routes declare typed search-parameter schemas now (`limit`, `cursor`, and their own filters) because deep links must retain filters (`UI_UX_SPECIFICATION.md` §2) and later tasks must not change the URL contract. **Never** put a payload or secret in a query parameter.
- Role-aware navigation is structural only: `/app/api-keys` is marked Admin-only so `FE-02`/`FE-05` attach the real role check. Phase 1 must not implement a client-side auth guard that implies authorization — the server is the sole authorization gate (`apps/web/AGENTS.md` §3).
- Do not implement a tenant selector. Organization identity comes from the session.

**Verify:** every route resolves; navigation between all routes works by keyboard; search parameters survive a reload; 404 renders for an unknown path.

## 6. Step 5 — Typed API client (D5)

One shared Axios instance. No raw `fetch`, no ad hoc instances in components (`apps/web/AGENTS.md` §2).

Required behavior:

- `baseURL` from `VITE_API_BASE_URL`, pointing at `/v1` for business calls.
- `withCredentials` for cookie-based sessions, since the management API uses a Secure/HttpOnly/SameSite cookie plus CSRF protection (`API_SPECIFICATION.md` §1). The CSRF token mechanism itself is **ADR-01-dependent**: leave a single, clearly marked extension point and implement nothing speculative.
- **Never** attach a `flw_...` producer key. Machine publishing keys belong to server-side producers only; the dashboard client must have no code path that can send one (`apps/web/AGENTS.md` §3). Add a test asserting no request header carries a `flw_` value.
- Response-error normalization to one typed shape from the envelope `{ error: { code, message, request_id, details } }`, covering `400`, `401`, `403`, `404`, `409`, `413`, `422`, `429` and `5xx` — plus network/timeout errors, which have no envelope. Preserve `request_id` for support, and surface actionable messages without leaking internals.
- `401` is treated as "session expired" at the client layer: clear cached data and route to the login placeholder. `403` renders access-denied; `404` renders not-found and is **not** treated as proof a resource exists elsewhere.
- Use types from `packages/contracts` (error envelope, cursor envelope, health types). Do not hand-copy backend DTOs; later tasks consume generated contract types from `BE-14`.
- Cursor pagination helper over `{ data, next_cursor }` only. No offset pagination, no fabricated totals.

**Verify:** unit tests cover each status mapping, the network-error path, `request_id` preservation, and the no-`flw_`-header assertion.

## 7. Step 6 — Server state (D6)

- One `QueryClientProvider` at the app root.
- Centralized query-key factory, scoped by resource and, where relevant, organization — so later tasks invalidate narrowly instead of clearing the cache (`apps/web/AGENTS.md` §6).
- Defaults: sensible `staleTime`; retry transient failures only — never retry `4xx`; no automatic retry of mutations (publishing and replay require an approved idempotency policy).
- **Secret hygiene in cache:** nothing that can hold a raw API key or signing secret may enter the query cache or any persister. Phase 1 must not configure cache persistence at all; one-time secrets later live in ephemeral component state only (`apps/web/AGENTS.md` §4).
- Timestamps: the API returns RFC3339 UTC. Establish one formatting helper now with explicit timezone display, so screens do not each invent one.

**Verify:** a mocked query renders loading → success; a mocked `422` does not retry; no persister is registered.

## 8. Step 7 — Error and state primitives (D7)

- Root error boundary rendering a safe fallback with the `request_id` when available — never a stack trace or raw response.
- Reusable `Loading`, `Empty`, `ErrorState` components; every later screen must implement all four of loading, empty, success and error (`AGENTS.md` §6.5).
- A dedicated 404 route and an access-denied view the router can render, for `FE-02` to use.
- Toast/notification provider for action feedback.
- Never render API-supplied HTML. No `dangerouslySetInnerHTML`. Webhook payloads will be displayed as escaped text/JSON with truncation (`apps/web/AGENTS.md` §4).

**Verify:** a thrown render error is caught by the boundary; each state component renders and is announced accessibly.

## 9. Step 8 — Mock API layer (D8)

The backend business endpoints do not exist yet, so phase-1 navigation and tests run against mocks.

- Use one request-interception layer (for example MSW) sharing handlers between development and tests. Enable it only when an explicit development flag is set — never in a production build.
- Fixtures must be typed against `packages/contracts` and must mirror the documented envelopes exactly: cursor pagination, the error envelope, RFC3339 UTC timestamps.
- Fixtures must represent honest domain semantics even in placeholders (`apps/web/AGENTS.md` §5): an event may have zero deliveries; a failed **attempt** is not a failed **delivery**; `UNKNOWN` attempt outcomes exist; `202` means accepted or scheduled, never delivered.
- No fixture may contain a realistic-looking API key or signing secret. Use obvious non-secrets and never snapshot a full credential value.

**Verify:** mocked handlers serve the envelopes; a disabled flag produces no interception; fixtures typecheck against the contracts package.
