# BE-09 — Worker: Lease, Safe Egress, HMAC Signing, Attempt Records

**Task (`IMPLEMENTATION_PLAN.md` §3):** worker atomic lease, safe HTTP egress, HMAC canonical signing, target snapshot, attempt writes.
**Dependencies:** `BE-06`, `BE-08`.
**Blocked by:** **ADR-04** (timeout, response cap, concurrency — implement as configuration with the `PRD.md` §7 proposals as defaults) and **ADR-05** (exact outbound header/body version — the contract in `API_SPECIFICATION.md` §6 is the current normative text; confirm before external integration).
**Requirements:** `FR-DEL-02`..`06`, `FR-RET-01/02`, `FR-SEC-02`, `FR-OBS-04/05`, `NFR-05/06`. Tests: `QA-E2E-04/05`, `QA-SEC-01`..`05`, `QA-RES-06`, `AT-04`..`06`, `AT-09`, `AT-11`.

**Normative inputs:** `TECHNICAL_DESIGN.md` §5 (worker algorithm and error policy), §6 (SSRF-safe egress), §7 (signing); `API_SPECIFICATION.md` §6 (outbound contract); `SYSTEM_ARCHITECTURE.md` §4.3; `DATABASE_DESIGN.md` §5 worker claim.

This task performs the only outbound network I/O in the product, to a URL chosen by a tenant. Treat every destination as hostile.

## Scope boundary

In scope: the `apps/worker` job processor — claim, state and safety validation, attempt creation, envelope construction, signing, the pinned-IP HTTPS send, result classification, and attempt finalization.

Out of scope: computing the next retry time and recovering expired leases (`BE-10`), replay (`BE-12`), read APIs (`BE-11`). The URL policy validator is owned by `BE-06` and reused here, not reimplemented.

## Implementation requirements

1. **Algorithm** (`TECHNICAL_DESIGN.md` §5, follow in order): receive `{deliveryId, generation, attemptNumber}` → atomically claim the delivery lease if due, status valid and generation current → no-op if stale, terminal or already leased → verify application and endpoint are still enabled and the destination snapshot is safe → create a `STARTED` attempt unique on `(generation, attempt_number)` → build the raw envelope, timestamp and HMAC using the snapshotted secret version → connect to a verified public IP with TLS for the URL hostname, redirects disabled → POST with bounded timeout and response size → conditionally finalize the attempt and delivery state.
2. **Atomic claim.** Use a single conditional `UPDATE ... WHERE status IN ('PENDING','RETRY_WAIT') AND (lease_expires_at IS NULL OR lease_expires_at < now()) AND generation = $job_generation AND next_attempt_at <= now() RETURNING ...` (`DATABASE_DESIGN.md` §5). Exactly one worker may hold a live lease. A `SUCCEEDED`, `FAILED`, `CANCELLED`, disabled or stale-generation job is a silent no-op, not an error.
3. **Lease discipline.** Use an unguessable `lease_owner` token and a `lease_expires_at` greater than the HTTP timeout plus processing margin; heartbeat if a pause could exceed it. **Never hold a database transaction open across network I/O** (`AGENTS.md` §5). Finalization is conditional on still owning the lease — a worker that lost it must not write delivery state.
4. **Disabled check at claim time.** If the application or endpoint is disabled, cancel the unsent delivery and make **no HTTP request** (`FR-END-06`, `AT-11`, `QA-E2E-09`).
5. **Send-time destination revalidation** (`FR-SEC-02`, `TECHNICAL_DESIGN.md` §6) — mandatory even though `BE-06` validated at configuration:
   - Re-run the shared URL policy validator on the snapshotted URL.
   - Resolve A/AAAA and require every candidate IP to be globally routable.
   - **Pin the connection to a validated IP while preserving the original SNI/Host and full TLS certificate verification for the hostname**, defeating DNS rebinding between check and connect (`QA-SEC-02`).
   - Redirects disabled entirely in v0.1 (`QA-SEC-03`).
   - Refuse proxy environment variables unless a reviewed policy approves them.
   - Bound response bytes, header size, timeout and outbound concurrency. Never log a response body (`FR-OBS-05`).
   - On any unsafe condition: terminal failure with `unsafe_destination`, and no packet to the target (`AT-09`).
6. **Envelope and headers exactly as specified** (`API_SPECIFICATION.md` §6): body `{ id, type, application_id, data, created_at }`; headers `FlowUp-Event-Id`, `FlowUp-Delivery-Id`, `FlowUp-Event-Type`, `FlowUp-Timestamp`, `FlowUp-Signature: v1=<lowercase-hex>`, `FlowUp-Attempt`, `FlowUp-Generation`; `Content-Type: application/json`.
7. **Signing.** `HMAC_SHA256(secret, ascii(timestamp) + "." + raw_request_body_bytes)`, lowercase hex, using the secret version snapshotted on the delivery. **Sign the exact bytes that are sent** — never re-serialize between signing and sending (`FR-DEL-03`, `apps/api/AGENTS.md` §6). Decrypt the secret version in memory only; never log or cache it.
8. **Result classification** (`TECHNICAL_DESIGN.md` §5 table): `2xx` → `SUCCEEDED` (transport only, never business completion — `FR-DEL-05`); `429` → retryable, optionally honoring a bounded numeric `Retry-After`; `5xx` → retryable; timeout, connection reset, temporary DNS → retryable if the destination is safe; other `4xx` → terminal `FAILED` by default; unsafe destination, malformed URL or TLS failure → terminal `FAILED` with no unsafe fallback. Do not blanket-retry all `4xx` (`FR-RET-02`).
9. **Attempt records.** Persist `started_at`, `finished_at`, `duration_ms`, `http_status`, `result`, `error_code`, `worker_id`, immutable after finalization, with **no raw remote response body** (`DATABASE_DESIGN.md` §3, `FR-OBS-04`). Store a safe error category, not a free-form dump.
10. **Independence.** One endpoint's outcome must never alter another delivery for the same event (`FR-DEL-06`, `AT-04`). No shared mutable state across jobs.
11. **Concurrency.** Respect `WORKER_CONCURRENCY` and the bounded outbound connection limit. Jobs are `attempts: 1`; the worker never schedules its own queue-level retry.
12. **Observability.** Structured logs with `delivery_id`, `attempt_id`, `generation`, `worker_id`, sanitized error category and trace ID. Metrics for attempt outcomes, duration and lease expiries (`SYSTEM_ARCHITECTURE.md` §7).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | `2xx` marks the delivery `SUCCEEDED` with one finalized attempt | `QA-E2E-04`, `AT-04` |
| 2 | `503` and `429` and timeout are classified retryable; `400` is terminal with no automatic retry | `QA-E2E-05/06`, `AT-05` |
| 3 | A/B endpoints for one event succeed and fail independently | `QA-E2E-04`, `AT-04` |
| 4 | An independently computed signature over the raw received bytes matches; a tampered body or timestamp fails | `QA-SEC-05`, `AT-06` |
| 5 | Private, loopback, link-local, reserved and metadata destinations produce no outbound packet | `QA-SEC-01`, `AT-09` |
| 6 | A hostname rebinding to an internal IP between validation and connect is rejected at connect time | `QA-SEC-02` |
| 7 | A redirect to an internal host is not followed | `QA-SEC-03` |
| 8 | A disabled endpoint causes cancellation with no HTTP request | `AT-11`, `QA-E2E-09` |
| 9 | Two workers starting the same job yield exactly one live lease and no overlapping active attempt | `QA-RES-06` |
| 10 | No response body, secret or signature appears in logs or attempt rows | `QA-SEC-07`, `FR-OBS-05` |
| 11 | No database transaction is held open across the HTTP call | `AGENTS.md` §5 |

## Tests

- **Unit:** result classifier across the full status matrix; HMAC against a fixed raw-byte test vector (`QA-SEC-05`); envelope serialization byte-stability; lease-token comparison; `Retry-After` bounding.
- **Integration (worker + PostgreSQL + Redis + receiver simulators per `TEST_PLAN.md` §2):** 2xx, 204, 400, 429, 503, delayed/hung, disconnect; disabled endpoint; stale generation; concurrent claim of one job; response exceeding the byte cap.
- **Security:** `QA-SEC-01`..`05` using a controlled test resolver and egress fixture — never probe real internal infrastructure (`TEST_PLAN.md` §9).

## Definition of Done

The worker claims atomically, revalidates destination safety at send time with IP pinning and TLS hostname verification, signs the exact outbound bytes per the documented contract, classifies results per the approved policy, and persists immutable attempts without response bodies or secrets; redirects disabled; limits configurable per ADR-04; deliveries are mutually independent; no transaction spans network I/O; all listed tests pass, including an independent signature verifier.
