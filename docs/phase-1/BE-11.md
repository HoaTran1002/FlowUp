# BE-11 — Read APIs: Events, Deliveries, Attempts, Usage Summary

**Task (`IMPLEMENTATION_PLAN.md` §3):** event/delivery/attempt read APIs with cursor/filter, usage summary, redaction.
**Dependencies:** `BE-03`, `BE-07`, `BE-09`.
**Blocked by:** nothing structural. Payload-read authorization and retention interact with **ADR-04**; expose `data` only where the approved role and retention policy permit (`API_SPECIFICATION.md` §5).
**Requirements:** `FR-OBS-01`..`06`, `FR-SEC-01`, `FR-SEC-05`. Tests: `QA-E2E-12`, `QA-API-03`, `QA-AUTH-02`, `QA-SEC-07`, `AT-12`.

**Normative inputs:** `API_SPECIFICATION.md` §1 (pagination, status conventions) and §5 (events, deliveries, attempts, usage); `PRD.md` §3 F08; `DATABASE_DESIGN.md` §6 indexes; `UI_UX_SPECIFICATION.md` §3 UI-02/07/08/09.

## Scope boundary

In scope: `GET /v1/events`, `GET /v1/events/{id}`, `GET /v1/deliveries`, `GET /v1/deliveries/{id}`, `GET /v1/deliveries/{id}/attempts`, `GET /v1/usage/summary`.

Out of scope: replay (`BE-12`), the UI (`FE-06`..`FE-09`), retention deletion jobs (`BE-13`). Add no aggregation beyond the documented counts — dashboard analytics are P1/post-MVP (`PRD.md` §9).

## Implementation requirements

1. **Routes and shapes exactly as specified** (`API_SPECIFICATION.md` §5). Deliveries list items carry `id`, `event_id`, `endpoint_id`, `status`, `generation`, `attempt_count`, `next_attempt_at`, `last_error_code`. Attempts carry `generation`, `attempt_number`, `started_at`, `duration_ms`, `http_status`, `result`, `error_code`. Usage returns accepted events, successful deliveries, failed deliveries, pending deliveries and retries. Invent no field.
2. **Tenant scoping.** Every query filters by the principal's `organization_id`; a non-owned ID returns `404` with no existence leak (`FR-SEC-01`, `QA-AUTH-02`). Nested resources are scoped through their owned parent, never by the child ID alone.
3. **Cursor pagination** (`API_SPECIFICATION.md` §1). `?limit=20&cursor=...`, default 20, max 100, deterministic `(created_at, id)` ordering, response `{ data, next_cursor }`. Pages must neither lose nor duplicate rows when data is inserted between requests (`QA-API-03`, `QA-E2E-12`). No offset pagination and no total count.
4. **Filters.** Events by `application_id`, `type`, `from`, `to` (`FR-OBS-01`). Deliveries by application, endpoint, status, event and date (`FR-OBS-02`). Define and document default sorting and date-range semantics consistently across events, deliveries and usage (`UI_UX_SPECIFICATION.md` §7.4). Filters are always combined with the tenant scope.
5. **Honest semantics.** An event's `delivery_count` and its `no_matching_reason` are reported as stored; event status never collapses per-recipient outcomes into a single boolean (`PRD.md` §6, `FR-EVT-07`). Attempt `UNKNOWN` is returned as `UNKNOWN`, not as a failure (`FR-OBS-04`).
6. **Detail content.** `GET /v1/events/{id}` returns the immutable `data` only where role and retention policy permit; attach deliveries as links or summary counts rather than inlining large attempt lists (`API_SPECIFICATION.md` §5). `GET /v1/deliveries/{id}` returns the snapshotted destination according to permissions, plus event type, state, generation, attempt count and next retry time.
7. **Redaction.** Never return a signing secret, an API key, a signature, or an arbitrary downstream response body. Error categories are safe codes, not raw messages (`FR-OBS-05`, `QA-SEC-07`).
8. **Performance.** Use the indexes from `DATABASE_DESIGN.md` §6. No N+1 queries, no unbounded scan on `event`, `delivery` or `delivery_attempt`; attempt counts come from a bounded aggregate, not from loading every row (`apps/api/AGENTS.md` §7).
9. **Usage summary.** Compute over the requested range with the documented date semantics. No billing implication, no projection, no fabricated metric (`API_SPECIFICATION.md` §5).
10. **Roles.** Admin and Developer may read; payload access follows the approved authorization rule (`API_SPECIFICATION.md` §7 lists explicit RBAC for payload access as a pre-freeze decision — if unresolved, apply the stricter rule and report it).

## Tests

- **Unit:** cursor encoding and decoding; filter composition; date-range normalization; response mapping with redaction.
- **Integration:** seeded multi-tenant data set; paging with concurrent inserts; filter matrix; attempt ordering across two generations; usage counts verified against direct SQL.
- **Contract:** `QA-API-01`, `QA-API-03` against the OpenAPI schema from `BE-14` where available, otherwise against committed fixtures.
- **Security:** `QA-AUTH-02`, `QA-SEC-07`; a response-scan test asserting no credential-shaped value is ever serialized.

## Definition of Done

Six read routes matching the contract exactly; tenant-scoped with correct `404` semantics; deterministic cursor pagination with documented filters and date semantics; honest event, delivery and attempt semantics including `UNKNOWN`; full redaction; indexed queries with no N+1; usage counts accurate; listed tests pass.
