# BE-14 — Published OpenAPI, Producer Sample and Independent HMAC Verifier

**Task (`IMPLEMENTATION_PLAN.md` §3):** publish OpenAPI, sample producer cURL and raw-byte consumer HMAC verifier; CI contract generation.
**Dependencies:** `BE-02`, `BE-07`, `BE-09`, `BE-12`.
**Blocked by:** **ADR-05** — the exact outbound header/body version and the published OpenAPI. This task is where ADR-05 is closed; it cannot ship with it open.
**Requirements:** `NFR-06`, API v0.1. Tests: `QA-API-01`..`04`, `QA-SEC-05`, `AT-06`.

**Normative inputs:** `API_SPECIFICATION.md` in full, especially §6 (outbound contract) and §7 (pre-freeze checklist); `TECHNICAL_DESIGN.md` §7; `PRD.md` §7 `NFR-06`.

## Scope boundary

In scope: the normative OpenAPI document and its generated types, contract tests in CI, the producer publish sample, and an independent consumer-side signature verifier with fixed test vectors.

Out of scope: new endpoints or fields. If the specification is found incomplete, raise a contract addendum through review — do not invent a route, field or status here.

## Implementation requirements

1. **Normative schema first.** Generate OpenAPI from a normative schema definition and commit it; do not hand-maintain a second copy that can drift (`API_SPECIFICATION.md` §7). The committed document covers every route in §2 plus the `BE-02` auth addendum.
2. **Close the pre-freeze checklist** (`API_SPECIFICATION.md` §7). Before publishing: human session endpoints and CSRF (ADR-01), idempotency retention (ADR-04), explicit RBAC for payload access, secret rotation semantics (ADR-02), application-disable pending policy (ADR-03), and a **stable error code catalog**. Any item still open blocks publication — report it rather than guessing.
3. **Error catalog.** Publish the complete, stable list of `error.code` values with their HTTP statuses and meanings. Codes are a public contract; renaming one later is a breaking change.
4. **Generated types.** Produce client types into `packages/contracts` so `apps/web` consumes generated types instead of hand-written DTOs (`apps/web/AGENTS.md` §2). Generated types must compile under the strict configuration and be checked in or reproducibly generated in CI.
5. **Contract tests in CI** (`QA-API-01`). Assert every implemented route against the schema: request and response bodies, status codes, optional fields and the error envelope. Assert cursor pagination semantics (`QA-API-03`) and the `202` publish response shape, including that no field implies delivery (`QA-API-02`). CI fails on drift between implementation and schema.
6. **Outbound contract documentation** (`QA-API-04`). Document `FlowUp-Event-Id`, `FlowUp-Delivery-Id`, `FlowUp-Event-Type`, `FlowUp-Timestamp`, `FlowUp-Signature`, `FlowUp-Attempt`, `FlowUp-Generation`, the exact envelope body, and the `v1` signature definition `HMAC_SHA256(secret, ascii(timestamp) + "." + raw_request_body_bytes)` in lowercase hex.
7. **Producer sample.** A runnable cURL example for `POST /v1/events` showing the Bearer key, mandatory `Idempotency-Key`, and the `202` response. The sample must use an obviously fake key, explain that `202` means accepted and not delivered, and show the `409` conflict and zero-subscriber cases.
8. **Independent HMAC verifier.** A consumer-side sample that:
   - reads the **raw HTTP request bytes** and never re-serializes parsed JSON (`API_SPECIFICATION.md` §6);
   - compares in constant time;
   - enforces a timestamp freshness window (suggested 5 minutes) using UTC, acknowledging clock skew;
   - deduplicates by `FlowUp-Delivery-Id` or `FlowUp-Event-Id` according to the consumer's processing boundary;
   - states plainly that replay intentionally reuses IDs and that a webhook may be received more than once.
   Ideally implemented outside the API codebase — a second language or an isolated script — so it genuinely verifies rather than reusing the signing code (`NFR-06`).
9. **Canonical test vectors.** Commit fixtures fixing the exact raw bytes, timestamp, secret and expected signature. These vectors pin the contract: a change to them is a breaking change (`QA-SEC-05`).
10. **CI integration.** Schema generation, type generation, contract tests and the verifier's vector test all run in CI on a clean checkout. No step may require a real credential or an external network destination.

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | Committed OpenAPI covers every implemented route and matches it exactly | `QA-API-01` |
| 2 | Generated contract types compile and are consumed by `apps/web` | `NFR-06` |
| 3 | The stable error code catalog is published and complete | `API_SPECIFICATION.md` §7 |
| 4 | Contract tests fail when implementation drifts from the schema | `QA-API-01` |
| 5 | The publish `202` response shape is asserted and claims no delivery | `QA-API-02` |
| 6 | Outbound headers and the signature definition are documented and asserted | `QA-API-04` |
| 7 | The independent verifier validates real delivered traffic and the committed vectors | `QA-SEC-05`, `AT-06` |
| 8 | A tampered body, tampered timestamp or stale timestamp fails verification | `QA-SEC-05` |
| 9 | The producer sample runs against a local environment and is accurate | — |
| 10 | ADR-05 is closed and recorded; no pre-freeze checklist item remains open | `API_SPECIFICATION.md` §7 |

## Tests

- **Contract:** `QA-API-01`..`04` in CI against the committed schema.
- **Cross-implementation:** the verifier against committed vectors and against bytes captured from a real `BE-09` send.
- **Negative:** tampered body, tampered timestamp, wrong secret version, expired freshness window.

## Definition of Done

OpenAPI generated from a normative schema, committed and matching the implementation under CI contract tests; a stable error code catalog published; generated types consumed by the frontend; the outbound envelope, headers and signature documented and pinned by canonical vectors; an independent raw-byte verifier that passes against real traffic and fails on tampering; an accurate producer sample; ADR-05 closed with every pre-freeze item resolved or explicitly reported as blocking.
