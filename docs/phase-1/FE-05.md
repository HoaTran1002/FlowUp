# FE-05 — Admin API Keys with One-Time Key Dialog

**Task (`IMPLEMENTATION_PLAN.md` §4):** Admin API keys create/revoke, scope picker, one-time key dialog.
**Dependencies:** `BE-05`, `FE-02`, `FE-03`.
**Requirements:** `UI-06`, `FR-KEY-01`..`04`. Tests: `UX-AC-03`, `QA-UI-02`, `QA-UI-07`, `QA-SEC-07`, `QA-AUTH-05`, `QA-E2E-11`.

**Normative inputs:** `UI_UX_SPECIFICATION.md` §3 UI-06 and its workflow subsection, §5; `API_SPECIFICATION.md` §4 (api-keys); `PRD.md` §3 F02.

## Scope boundary

In scope: `/app/api-keys` — Admin-only list, create form with the application scope picker, the one-time raw key dialog, and revoke with confirmation.

Out of scope: endpoint signing secrets (`FE-04` — a different credential), publishing. The dashboard must have no code path that sends a `flw_` key as a request credential.

## Implementation requirements

1. **Admin only.** The route is hidden from Developer navigation and renders access denied if reached directly; the server's `403` is the authority (`UX-AC-03`, `QA-AUTH-05`). Never render key metadata before the authorization check resolves.
2. **List (`UI-06`).** Key name, scoped application IDs, prefix, last used, status and created date — metadata only, never the raw key or hash (`FR-KEY-03`).
3. **Create.** Label plus an application scope picker listing the organization's applications; an explicit, non-empty selection is required (`FR-KEY-01`). Validate with Zod aligned to the contract; the server stays authoritative.
4. **One-time key dialog** (`UI_UX_SPECIFICATION.md` §3 UI-06, `QA-UI-02`): show the raw key once with `Reveal` and `Copy` and an explicit acknowledgement before closing. Keep the value in ephemeral component state; clear it on close, navigation and unmount; never refetch it. The key must never enter the query cache, a persister, browser storage, a URL, a toast, analytics, telemetry, an error report or a snapshot (`apps/web/AGENTS.md` §4, `QA-SEC-07`).
5. **Revoke.** Confirmation dialog whose copy states the real effect: new publishes are blocked, while deliveries already accepted may continue (`FR-KEY-03`, `PRD.md` §6 edge case 10, `QA-UI-07`). Refresh the list after success.
6. **No producer key in the client.** Add an explicit guard and test: no request from the dashboard may carry a `flw_` credential (`apps/web/AGENTS.md` §3). Publishing examples remain documentation-only, as in `FE-03`.
7. **States.** Loading, empty, success, error, validation error, and access denied.
8. **Accessibility.** Dialog focus management, labeled picker, keyboard operation, status by text not colour.
9. **Query hygiene.** Invalidate only the key list after a mutation. Never cache a response containing a raw key — the creation response is consumed directly by the dialog and discarded (`apps/web/AGENTS.md` §6).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | A Developer sees no API Keys navigation and gets access denied on direct navigation, with no metadata rendered | `UX-AC-03`, `QA-AUTH-05` |
| 2 | Creating a key opens the one-time dialog with the raw value | `QA-UI-02` |
| 3 | Closing requires acknowledgement; afterwards the value is unreachable | `QA-UI-02`, `QA-SEC-07` |
| 4 | The raw key is absent from the query cache, storage, URL, toast and analytics | `QA-SEC-07` |
| 5 | A refresh never redisplays the key; the list shows the prefix only | `FR-KEY-02/03` |
| 6 | Creation requires a non-empty application scope selection | `FR-KEY-01` |

| 8 | No dashboard request carries a `flw_` credential | `apps/web/AGENTS.md` §3 |

## Tests

- **Unit:** create-form schema including the non-empty scope rule; dialog state machine with acknowledgement gating and clearing on unmount.
- **Component:** Admin vs Developer rendering; one-time dialog lifecycle asserting unreachability after close; revoke dialog copy.
- **Integration (mocked API):** create → dialog → list shows prefix only; revoke → status refresh; `403` for Developer.
- **Security:** `QA-SEC-07` cache, storage and snapshot assertions; the no-`flw_`-header assertion from `FE-01` extended to this feature.

## Definition of Done

The route is Admin-only in both UI and server handling; list shows metadata only; creation requires an explicit scope and reveals the raw key exactly once behind an acknowledgement, leaving no trace; revoke confirms with accurate consequences; no producer key path exists in the browser; all states render; listed tests pass including every secret-absence assertion.
