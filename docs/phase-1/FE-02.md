# FE-02 — Session Guard, Role-Aware Navigation, Access-Denied Views

**Task (`IMPLEMENTATION_PLAN.md` §4):** login/session guard, role-aware navigation, invite-required/access-denied views.
**Dependencies:** `BE-02`, `FE-01`.
**Blocked by:** **ADR-01** — `UI_UX_SPECIFICATION.md` §7.1 names `UI-01` an explicit blocker until the sign-in, sign-out, invite-acceptance, session-refresh and CSRF protocol exists. Do not start before the `BE-02` addendum is approved; do not invent auth endpoints.
**Requirements:** `UI-01`, `UI-10`, `FR-ORG-02`, `FR-ORG-03`. Tests: `UX-AC-03`, `UX-AC-10`, `QA-AUTH-01`, `QA-AUTH-04`, `QA-AUTH-05`, `QA-UI-05`.

**Normative inputs:** the approved `BE-02` auth addendum in `API_SPECIFICATION.md`; `UI_UX_SPECIFICATION.md` §2, §3 UI-01/UI-10, §5, §7.1; `apps/web/AGENTS.md` §1, §3, §4.

## Scope boundary

In scope: the `/login` screen, the authenticated layout guard for `/app/*`, session-expiry handling, organization identity in the shell, role-aware navigation, and the invite-required and access-denied views.

Out of scope: every business screen (`FE-03`..`FE-09`), key and secret dialogs (`FE-04`, `FE-05`). This task makes the shell from `FE-01` genuinely authenticated and nothing more.

## Implementation requirements

1. **Use the approved contract only.** Implement exactly the routes and session semantics the `BE-02` addendum defines. If a behavior is not in it, request a contract change rather than assuming one (`apps/web/AGENTS.md` §1).
2. **No JavaScript-readable persistent token.** The session rides the `Secure`/`HttpOnly`/`SameSite` cookie with CSRF protection (`API_SPECIFICATION.md` §1). Do not store a token in `localStorage`, `sessionStorage` or a cookie the page can read, and do not place a producer `flw_` key anywhere in the dashboard client (`apps/web/AGENTS.md` §3/§4).
3. **CSRF.** Wire the approved mechanism into the single shared Axios client's extension point from `FE-01`. One implementation, no per-call handling.
4. **Route guard.** `/app/*` resolves the session before rendering. While resolving, show a loading state — never a flash of authenticated content and never a redirect loop. An unauthenticated visitor is sent to `/login` with the intended destination preserved for post-login return, without placing sensitive data in the URL.
5. **Session expiry.** A `401` from any request clears user-facing authenticated data and the query cache, then routes to sign-in with an explanatory message (`UI_UX_SPECIFICATION.md` §5, `UX-AC-10`). Never retry a `401` in a loop.
6. **Access denied.** A `403` renders the access-denied view — not a retry, not a redirect to login (`UI_UX_SPECIFICATION.md` §5). Deep-linking to an Admin-only route as a Developer must show access denied, and the server's `403` is the authority (`UX-AC-03`).
7. **Invite-required.** An authenticated user with no organization membership sees the invite-required explanation from `UI-01`. Do not offer self-signup — it is post-MVP (`PRD.md` §9).
8. **Role-aware navigation.** Render the navigation from `UI_UX_SPECIFICATION.md` §2 — **Overview | Applications | Endpoints | Events | Deliveries | API Keys (Admin)** — hiding API Keys for Developers. State in code that hiding is UX only: server authorization is the sole gate (`apps/web/AGENTS.md` §3, `FR-ORG-03`).
9. **Organization identity.** Display the organization from the session in the shell header. No tenant selector, no organization switcher, no caller-supplied `organization_id` anywhere in a request (`UI_UX_SPECIFICATION.md` §2).
10. **Sign-out.** Call the approved endpoint, clear the entire query cache, and route to `/login`. Leave no authenticated data in memory or cache.
11. **Error states.** Cover `401`, `403`, `429` and `5xx` for auth routes with actionable copy and no success claim on failure (`UI-10`, `QA-UI-05`).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | Unauthenticated access to `/app/*` routes to `/login` without a content flash or loop | `QA-AUTH-01` |

| 9 | Organization identity comes from the session; no request carries a client-supplied organization ID | `FR-SEC-01` |

## Tests

- **Unit:** guard decision table (resolving, unauthenticated, authenticated, member-less, insufficient role); `401`/`403` handler behavior.
- **Component:** navigation per role; access-denied, invite-required and session-expired views; loading state during resolution; no authenticated content before resolution.
- **Integration (mocked API):** full sign-in → protected request → `401` expiry → redirect; deep-link return after login.
- **Security:** a test asserting no storage mechanism holds a token and no request header carries a `flw_` value.

## Definition of Done

Only the approved auth contract is used; `/app/*` is guarded with correct loading, expiry and deep-link behavior; `401`, `403` and invite-required states are distinct and accurate; navigation is role-aware while server authorization remains the stated gate; no readable token, no producer key, no client-supplied tenant ID; CSRF wired once in the shared client; listed tests pass. If ADR-01 is unresolved, deliver nothing and report the blocker.
