# FE-06 — Events List and Detail with Cursor Pagination

**Task (`IMPLEMENTATION_PLAN.md` §4):** events list/detail, filters, cursor pagination, accepted/zero-subscriber states.
**Dependencies:** `BE-11`, `FE-03`.
**Blocked by:** nothing structural. Payload visibility follows the approved RBAC and retention rule (`API_SPECIFICATION.md` §5, §7); if unresolved, apply the stricter rule and report it.
**Requirements:** `UI-07`, `FR-OBS-01`, `FR-EVT-07`. Tests: `UX-AC-04`, `UX-AC-09`, `QA-E2E-03`, `QA-E2E-12`, `QA-UI-03`, `QA-UI-08`.

**Normative inputs:** `UI_UX_SPECIFICATION.md` §3 UI-07 and the UI-07/UI-09 terminology subsection, §5; `API_SPECIFICATION.md` §1 and §5; `PRD.md` §6.

## Scope boundary

In scope: `/app/events` list with filters and cursor pagination, and `/app/events/:eventId` detail including the authorized payload view and the no-subscribers state.

Out of scope: deliveries and attempts (`FE-07`), replay (`FE-08`). The events screen must never display a delivery outcome it has not been given.

## Implementation requirements

1. **List.** Time, type and application filters; columns for event ID, type, application, accepted time and recipient count; a no-subscribers marker (`UI-07`). Use `GET /v1/events` through the shared client.
2. **Cursor pagination.** `next_cursor` only. Filter changes reset the cursor; accessible Previous and Next controls; never infer a total from a page (`UI_UX_SPECIFICATION.md` §5, `QA-API-03`).
3. **Filter persistence.** Keep filters and cursor in typed search parameters so deep links and back navigation restore them (`UX-AC-09`, `QA-UI-08`). No payload or secret in a query parameter.
4. **Terminology — this is the correctness core of the screen** (`UI_UX_SPECIFICATION.md` §3 UI-07/UI-09):
   - Event `ACCEPTED` is **not** a per-recipient delivery status, and must never be rendered as "delivered".
   - An event with zero deliveries shows **"No matching subscriptions"**, never "failed delivery" and never a fabricated delivery row (`FR-EVT-07`, `UX-AC-04`, `QA-E2E-03`).
   - Recipient count is the server's `delivery_count`; show `0` honestly.
5. **Detail.** Event ID with a copy action, type, application, accepted time, delivery count or the no-match reason, and links to the event's deliveries. Render the payload only where the approved authorization and retention policy permit.
6. **Payload display.** Escaped, read-only text or formatted JSON with truncation for large values. Never `dangerouslySetInnerHTML`, never API-supplied HTML, no clipboard auto-copy (`apps/web/AGENTS.md` §4, `UI_UX_SPECIFICATION.md` §5). A payload may contain PII: do not send it to analytics, telemetry or error reports, and do not persist it client-side.
7. **Timestamps.** UTC values from the API, displayed through the single formatting helper from `FE-01` with an explicit timezone indication.
8. **States.** Loading, empty, success, error, plus `403` and `404` as `FE-02` established. An empty list from a filter must read as "no results for these filters", not as "no events ever" (`QA-UI-01`).
9. **Query hygiene.** Query keys include the resource and the active filters; no cache persistence; no polling on this screen — events are immutable once accepted.
10. **Accessibility.** Responsive table with horizontal scrolling, stable columns, truncation with tooltips for long IDs, no layout shift when filtering or sorting, status conveyed by text and not colour (`QA-UI-03`, `QA-UI-04`).

## Acceptance criteria

| # | Criterion | Test |
|---|---|---|
| 1 | An accepted event with no subscriptions shows "No matching subscriptions" and no invented delivery | `UX-AC-04`, `QA-E2E-03` |
| 2 | Event status is never presented as a delivery outcome | `QA-UI-03` |
| 3 | Cursor paging across a filtered list loses and duplicates nothing | `QA-E2E-12`, `QA-API-03` |
| 4 | Filter changes reset the cursor; filters survive back navigation and reload | `UX-AC-09`, `QA-UI-08` |
| 5 | The payload renders escaped and read-only, truncated when large | `apps/web/AGENTS.md` §4 |
| 6 | The payload is not sent to analytics, telemetry or error reports, and is not persisted | `FR-OBS-05` |

| 8 | Loading, empty, filtered-empty and error states all render accessibly | `QA-UI-01` |
| 9 | Long IDs truncate with tooltips and cause no layout shift | `QA-UI-04` |

## Tests

- **Unit:** filter-to-query-parameter mapping; cursor reset on filter change; timestamp formatting; payload truncation.
- **Component:** list states; no-subscribers marker copy; detail with and without payload authorization; escaped payload rendering with an injection fixture.
- **Integration (mocked API):** paging with fixtures, including a page boundary; filter change resetting the cursor; `404` path.

## Definition of Done

List and detail implemented against the contract with correct cursor pagination and persisted filters; event versus delivery terminology exact and the zero-subscriber state honest; the payload renders escaped, truncated and authorized, and never leaves the page; all states accessible; listed tests pass.
